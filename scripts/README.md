# scripts

## Responsibility

The local quality gate and the hooks that enforce it ([ADR 0006](../docs/adr/0006-run-quality-gates-locally.md)).

## Public APIs

- `gate.ps1 [-Configuration Release|Debug] [-Quarantined] [-Physical] [-Force]`: builds `Mayday.sln`, runs the `Test` project without `[Quarantine]`, physical and manual tests, then the Pester tests of these scripts. Exits non-zero on the first failing step. A pass is remembered per configuration for an unchanged working tree (every non-Markdown file git tracks or could track, excluding `.idea`, `knowledge`, `docs`, `Media`; `.claude` counts, since its settings hold the hooks) and skipped next time unless `-Force`. With `-Physical` (the pre-push gate, [ADR 0011](../docs/adr/0011-pre-push-gate-drives-the-robot.md)) it first runs `quarantine-ratchet.ps1`, even when the working tree already passed (the ratchet reads commits, which the fingerprint does not see), then fails unless `MAYDAY_ROBOT_IS_CLEAR_TO_MOVE` is `True` (Test user secrets over environment, as the tests read it) and Mayday's FTDI adapter is present with a port that opens. After building it fails when listing the physical tests fails or lists none outside quarantine, so it cannot pass without moving the robot. Then it runs the hardware-free tests, the quarantined hardware-free tests and each physical test method in its own `dotnet test` process, with TRX results. It fails on a failing test that is not quarantined, on any skipped test, on a quarantined test that passes, and on a physical method run that executes no test, listing every one. A physical pass is remembered apart from a hardware-free one. It finds the repository from `-RepoRoot` only: it clears inherited git location variables such as `GIT_DIR`, which git sets when it runs hooks of a linked worktree, before any step runs.
- `quarantine-ratchet.ps1 [-RepoRoot] [-Upstream origin/master]`: compares the C# files under `Test/` at `HEAD` with the merge-base of `HEAD` and the upstream. Exits 1, listing each, when a test or test class that exists there gains `[Quarantine]`, `[Trait("Quarantine", ...)]` or a `Skip =` in its test attribute, or a new test is quarantined without a `MAY-` issue in its reason. A test in a quarantined class counts as quarantined with the class's reason. Tests are named `Namespace.Class.Method`, so a move to another file in the same namespace keeps them, and same-named classes in different namespaces stay apart. Only commits count; the working tree does not. `gate.ps1 -Physical` runs it first.
- `claude-stop-gate.ps1`: the Claude Code `Stop` hook. Runs `gate.ps1` in Debug, in its own process; exits 2 with the tail of the output on any failure, a crash included, so Claude must fix it before finishing.
- `quality-gates/` (outside this directory): the portable complexity gate; `gate.ps1` also runs its Pester tests. See its [README](../quality-gates/README.md).
- `review-pr.ps1 [-PullRequest <n>] [-Force]`: has a separate headless `claude -p` session review the pull request (default: the current branch's) in a temporary worktree of its head commit and posts the output with `gh pr comment`. Skips drafts, closed pull requests and head commits already reviewed (markers in `<git common dir>/claude-reviews`). Advisory ([ADR 0010](../docs/adr/0010-local-claude-review-of-every-pull-request.md)).
- `claude-review-hook.ps1`: the Claude Code `PostToolUse` hook on `Bash|PowerShell`. After `gh pr create` or `git push`, starts `review-pr.ps1` for the command's working directory (the payload's `cwd`) in a hidden background process, logging to its own `review-*.log` in `<git common dir>/claude-reviews`, and always exits 0. git options before `push` (`git -C ../wt push`) are recognized.
- `pre-push.ps1`: the `pre-push` hook. Reads the pushed refs from standard input and passes a documentation-only push (every changed file is Markdown or under `docs/`, `knowledge/`, `Media/`) without building or testing; any other push runs `gate.ps1 -Physical` in Release. A ref is compared with the remote commit, or for a new branch with its merge-base with `origin/master`.
- `.githooks/pre-push` (outside this directory): runs `pre-push.ps1`. Enable with `git config core.hooksPath .githooks`. Every worktree uses the hooks directory `core.hooksPath` names, so once it holds this hook, a branch cut before `pre-push.ps1` existed cannot push until it is rebased onto `master`.

## Dependencies

PowerShell 5.1, git, the .NET SDK and Pester 5+ (`Install-Module Pester -MinimumVersion 5.0 -Scope CurrentUser`). The review also needs `gh` and `claude`, both logged in.

## Invariants

- Without `-Physical` the gate forces `MAYDAY_ROBOT_IS_CLEAR_TO_MOVE=False` and excludes physical and manual tests; the Stop hook never passes `-Physical`. With it, it never sets the flag, only reads it. It never runs `Main` or `EllieMain`.
- A failed run never records a pass.
- Scripts have tests in `Tests` ([ADR 0007](../docs/adr/0007-infrastructure-code-is-tested-like-product-code.md)). `gate.ps1` takes `-RepoRoot`, `-BuildCommand`, `-TestCommand`, `-ScriptTestCommand`, `-RatchetCommand`, `-ClearToMoveCommand`, `-ConnectedCommand`, `-ListTestsCommand` and `-TestRunCommand`, the Stop hook takes `-GateScript`, and `pre-push.ps1` takes `-RepoRoot`, `-Upstream`, `-GateScript` and `-RefLines`, so tests can replace the expensive steps; the defaults are the real behavior.
